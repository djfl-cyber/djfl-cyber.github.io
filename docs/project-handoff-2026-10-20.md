## 2. 原定目标与用户偏好

最初需要解决的问题：

1. 新建文章不能自动配套图片目录，图片路径需要手改，VS Code 预览不便。
2. 博客布局、背景、栏目大小、模块取舍和文字修改过度依赖源文件。
3. 长文章容易造成目录显示混乱。
4. 音乐播放器、桌宠、抽卡等功能难以扩展。
5. 希望最终用本地图形界面统一管理，同时保留 Markdown 和 VS Code 写作习惯。

后来确认的三条产品主线：

| 主线 | 原定要求 |
| --- | --- |
| 页面设计 | 操作接近简化版 PPT，可以调整布局、文字、图片、背景、尺寸、层级和模块；支持响应式页面 |
| 内容与指令 | 将新建文章、打开 VS Code、预览、检查、构建、同步、备份与发布等日常命令变成按钮操作 |
| 可扩展组件 | 定义组件规范，在管理端导入、配置、布置、启停和卸载符合规范的组件 |

界面偏好：博客先采用浅色质感，保留背景和装饰的设计空间，由用户后续自行设计；管理程序采用类似 Codex 的简洁侧栏与工作区布局，减少复杂功能区。

必须持续遵守的边界：

- 保留原博客地址、旧文章 permalink、图片兼容路径与章节锚点，不因更换界面随意改变网址。
- 管理程序仅在本地运行。博客源码只同步网站需要的内容、配置、素材、访客组件与构建文件；线上部署只使用静态博客产物。
- 所有开发修改限定在博客范围内；辅助脚本集中放在 `scripts/studio/dev/` 等脚本目录，验收副本和产物放在 `scripts/artifacts/`。
- 不修改 VS Code 全局设置、Git 全局配置或其他项目文件。
- 保留用户文章、布局、配置和本地草稿，使用隔离副本进行会改数据的验收。
- 用户此前要求开发改动“暂不提交”。下一轮若仅授权开发，不自动提交、推送或部署；用户自行通过发布界面完成的发布不等于授权助手以后自动发布。
- 本轮只授权整理交接文档，没有授权立即开始下文的建议开发项。

## 4. 已实现的功能

### 博客迁移与阅读

- Astro 已替代旧 Hexo 博客，并由用户完成上线。
- 首页、文章、归档、友链、导航、关于等页面已有实现。
- 保留旧文章地址与资源兼容，草稿文章不生成生产页面。
- 长文目录支持独立滚动、章节定位、高亮与折叠。
- 文章标题变动不会自动改变网址；明确改址时保留旧址跳转。

### 写作与文章管理

- 新建文章自动创建 `index.md` 和本篇 `img`，支持创建后直接打开 VS Code。
- 内置 Markdown 编辑器支持基础工具栏、语法高亮、撤销、快捷保存和侧边预览。
- 支持搜索、分类/年份/草稿筛选与排序；可编辑标题、摘要、日期、分类、标签、封面、目录和草稿状态。
- 支持文章复制、回收和恢复；未保存内容可形成本机恢复草稿。
- 粘贴和拖入图片使用相对地址，文章新图片归属本篇 `img`。
- 从管理端打开 VS Code 时同时打开博客工作区和文章，以加载项目级粘贴图片设置。
- 外部文件变动有版本检查和冲突处理，不静默覆盖 VS Code 已落盘的修改。
- 管理端不能读取 VS Code 尚未保存的编辑缓冲区，发布前仍需保存文件。

### 页面设计与内容修改

- 画布支持选择、多选、框选、移动、缩放、复制、删除、分组、锁定、隐藏、层级、对齐、吸附和容器移动。
- 支持自动排版、网格与自由画布，可调整文字、尺寸、图片、背景、间距、边框和阴影等。
- 支持独立页面创建、复制、网址与菜单管理、回收与恢复、本地模板及恢复初始布局。
- 页头、页脚、关于页个人介绍和首页侧栏已有直接文字编辑入口。
- 友链与导航支持在当前页面新增、编辑、排序、隐藏和移除条目，可选择头像/图标和设置链接。
- 支持草稿预览与已保存效果，显示页面实际宽度，并可选择是否包含草稿文章。
- 页面设计预览和正式构建使用同一套站点渲染规则。

### 素材与恢复

- 素材库区分文章配图、页面素材和共用素材，可按文章归属与资源类型查找。
- 支持导入、预览、尺寸与引用查看、受管理引用的移动/重命名更新，以及 WebP 派生文件。
- 未引用素材扫描采用可恢复回收，清理前重新核对引用与版本。
- 博客内容备份与本机草稿/历史备份分开，支持文件历史对比、选择恢复及中断事务复核。

### 图形化操作与发布

- 日常预览、检查、构建、依赖准备、远端获取/安全快进、备份及高级迁移操作已有按钮入口。
- 任务展示阶段、状态、日志与取消入口。
- 发布先检查候选源码，再提交、推送和触发指定部署；记录 run ID、SHA 和请求标识。
- 已实现失败分阶段重试、继续追踪、线上版本核对与历史源码恢复。
- 普通推送只检查；发布操作才触发部署。发布摘要区分未保存草稿与磁盘内容。

### 组件与本地隔离

- 已实现组件规范、SDK、清单与完整性检查、文件夹/ZIP 导入、配置表单、实例、版本、启停和卸载。
- 组件以预构建 HTML/CSS/JS 运行于独立沙箱，可布置为页面区块或浮层。
- 音乐播放器示例已验证导入和播放；组件配置有本机草稿、冲突检查与生命周期处理。
- 旧浏览器文字工作台已退役，原有文字字段和备份能力已并入管理端。
- 管理程序、缓存、草稿、历史和便携产物被 Git 忽略；干净博客源码不依赖管理端也能构建。

## 6. 仍需完成或完善的部分

### 6.1 跨设备独立设计：优先完善的功能

当前已有手机和平板的样式、尺寸、位置、布局模式与可见性覆盖，以及“修改全部设备”和恢复继承机制。它并非只有视口模拟。

但页面内容数据与图层结构仍共用，新增/删除、分组和图层树重排等操作不是完全按设备隔离。桌面基础值也会被没有显式覆盖的其他设备继承。用户此前反映“调整一个设备影响其他设备”，当时要求先修复换行与预览，因此完整响应式改进仍未完成。

建议下一轮先明确每类操作的作用范围，再补齐独立排列及清楚的影响提示。验收应覆盖：只修改手机样式、显式覆盖后修改桌面、单设备排列、显示/隐藏、恢复继承、保存重开以及正式构建。共享文章和友链内容不应为了设备独立而无理由复制多份。

### 6.2 更接近简化 PPT 的操作体验

画布基础操作已具备，但部分图片焦点、背景、边距等仍依靠填写数值或样式文本。图片已有完整显示、填充裁切和焦点属性，不等于已有完整的拖拽裁切编辑器。

建议增加直观的图片裁切/焦点拖动、渐变与背景控件、间距操作，并简化属性面板。属于现有设计器上的完善，不需要推倒重做渲染体系。

### 6.3 Git 审阅与首次使用体验

- 发布页有变更文件摘要，但尚无完整的逐文件 Git 差异查看与内容冲突解决界面。
- 页面、配置和文章编辑的版本冲突处理已经存在，不能与 Git 分叉冲突混为一谈。
- 安全快进同步已提供；复杂 Git 分叉或冲突仍需 VS Code 等工具处理。
- 工具检测、依赖准备、发布目标和身份授权已有入口，但还没有集中成连续的首次设置向导。

### 6.4 具体功能组件

- 桌宠：尚无可交付成品。
- 抽卡：尚无可交付成品。
- 音乐播放器：已有示例与播放闭环；用户曲目、封面、样式可继续配置，歌词等附加功能需要另行明确和开发。

后续组件应复用现有规范与沙箱接口。开发前需要明确具体玩法、素材和交互需求，不能把“支持导入组件”当作“已制作所有组件”。
