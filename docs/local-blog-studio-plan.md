# 本地博客管理系统设计与实施方案

状态：设计方案，尚未实施。日期：2026-10-15。

本方案作为后续实现与验收依据。目标项目是 `C:\Users\jie\myblog\astro-site`，现有仓库分支为 `source`，远端为 `git@github.com:djfl-cyber/djfl-cyber.github.io.git`。用户已确认 Astro 博客上线可访问、现有 Markdown 写作流程可用。

## 1. 产品目标与设计决定

建立一个 Windows 本地桌面应用，暂称 Blog Studio。用户双击启动，通过同一个图形界面完成页面设计、文章和素材管理、VS Code 编辑衔接、预览、版本与发布、组件导入。

三条主线都属于完整首版的交付范围：

1. 具有实际画布操作能力的页面设计器，支持自由布局与响应式排版。
2. 将日常写作、构建、检查、版本同步和发布指令变成可追踪的按钮操作。
3. 可验证、可安装、可配置、可卸载的组件包接口，至少通过一个外部示例包验证整个流程。

不是继续扩充原文字表单作为最终产品。原文字工作台在迁移期间保留兼容，完整替代验收后退役。

默认决策无需阻塞设计：

- 首先支持当前 Windows 和当前单个 Astro 博客；结构允许以后选择其他兼容项目。
- 管理界面参考 Codex 的克制视觉、侧栏导航、中央工作区和可收起详情面板；使用自己的名称、图标与组件，不复制产品标识或内部实现。
- 继续采用 Astro 静态构建与现有 GitHub Pages 地址，旧文章 permalink 保持。
- 正文继续使用标准 Markdown，VS Code 是默认外部编辑器。管理端具备文章管理和基本正文编辑能力，不强制替换现有写作习惯。
- 管理应用及其日志、缓存、历史、凭据、构建包仅在本地；博客源码仓库只同步网站所需内容、配置、素材和访客组件。
- 所有由我们控制的文件写入位于博客目录内；不改 VS Code 全局设置、Git 全局配置或其他项目。

| 场景 | 用户操作 | 系统结果 |

## 3. 桌面界面

常驻区域保持简洁，按任务切换中央视图：

```text
┌───────────────────────────────────────────────────────────────┐
│ Blog Studio · 当前项目      保存状态      预览      发布        │
├───────┬───────────────┬───────────────────────────┬─────────────┤
│ 概览  │ 页面/图层     │                           │ 当前选中项  │
│ 文章  │ 或列表筛选    │        主工作区           │ 文本/样式   │
│ 设计  │               │   真实页面画布/文章列表   │ 布局/设备   │
│ 素材  │ 可收起        │                           │ 动态属性    │
│ 组件  │               │                           │ 可收起      │
│ 发布  ├───────────────┴───────────────────────────┴─────────────┤
│ 设置  │ 任务状态、操作历史、错误详情（默认收起）                 │
└───────┴────────────────────────────────────────────────────────┘
```

- 左侧主导航：概览、文章、页面设计、素材、组件、发布、设置。
- 页面设计视图：页面/模板选择，图层树，中央画布，右侧属性检查器。
- 顶部只放当前页面、撤销/重做、桌面/平板/手机切换、交互预览、保存、发布等高频操作。
- 文章视图使用列表和编辑详情；发布视图使用改动摘要和任务步骤，不把所有页面都做成画布。
- 配色为中性色、细边框和低强度阴影，状态色只用于选中、运行和错误。支持浅色/深色，默认浅色。
- 菜单中提供右键操作和快捷键，避免 PPT 式多层功能区。
- 编辑模式点击选中元素；交互预览模式点击链接、播放器等执行真实交互，避免两种行为冲突。

## 4. 可视化设计器

### 4.1 页面与模板范围

可编辑首页、独立页面、文章模板、归档/分类/标签模板，以及共用页头、页脚和侧栏。文章模板的修改影响全部使用该模板的文章，界面需标明影响范围；页面实例可以局部覆盖。

现有文章内容、友链条目、导航数据保持语义化数据，画布负责它们如何显示。不能把文章列表生成的一张卡片误当作独立静态内容，需通过所属列表设置样式并在代表性卡片上预览。

### 4.2 两种布局容器

**自动排版容器**：支持纵向、横向、网格、分栏，自动适应正文长度；可以拖动排序、调列宽、间距、对齐与留白。文章正文、文章列表默认使用此模式。

**自由画布容器**：支持元素任意拖放、缩放、叠放、旋转装饰、分组、前后层级与对齐。首页、横幅、背景装饰和功能浮层可以使用；其他区域也允许切换。

自由画布按父容器的局部坐标保存，定义容器高度、锚点、宽度策略和溢出行为。提供尺寸自适应内容边界的选项。不会用固定屏幕坐标替代所有网页排版。

容器模式转换前产生快照并提供预览，保存后可撤销。保留真正的自由操作能力，同时让长文区域继续自然增长。

### 4.3 具体画布操作

- 从组件库或素材库拖入元素。
- 框选/多选、移动、缩放、复制、删除、分组/解组、锁定、隐藏。
- 图层树拖动、置顶/置底、对齐、等距分布、参考线、吸附、键盘微调。
- 双击文本直接编辑，右侧设置字号、字重、颜色、行高、段距与链接。
- 图片替换、裁切、适应/填充、焦点、透明度、圆角、边框、阴影和替代文本。
- 页面/容器背景支持纯色、渐变、图片、遮罩；图片不需要人工写路径。
- 常用样式与布局保存为本地模板，支持复制页面和恢复初始布局。
- Ctrl+Z/重做、连续拖动合并为一次历史记录，文本输入时保留正常编辑和中文输入法行为。
- 桌面、平板、手机预设视口和自定义宽度；画布缩放与页面真实尺寸独立。

### 4.4 响应式规则

初始断点：桌面 ≥1024px、平板 640–1023px、手机 <640px。断点是可配置的站点设计数据，不能与画布截图尺寸混用。

桌面为基础值，平板/手机默认继承，必要时单独覆盖顺序、尺寸、定位、可见性与间距。修改时明确显示“当前设备覆盖”与“修改全部设备”，可清除覆盖重新继承。

自动排版支持分栏转单列、卡片换行、侧栏折叠；自由画布支持锚定和等比缩放，也可以为手机另设布局。不能承诺任何桌面自由画布都会自动变成良好的手机排版，保存前提供三个视口预览和越界提示。

### 4.5 数据模型与现有配置

结构以版本化 PageDocument 保存，而不是修改生成的 HTML 或将 DOM 截图保存成页面。

```ts
type LayoutNode = {
  id: string;
  type: string;                 // 内置或已安装组件类型
  props: Record<string, unknown>;
  layout?: { mode: 'flow' | 'grid' | 'free'; [key: string]: unknown };
  style?: Record<string, unknown>;
  responsive?: Record<string, Record<string, unknown>>;
  binding?: { source: string; path?: string };
  children?: LayoutNode[];
  locked?: boolean;
  visible?: boolean;
};
```

- 新增 `src/config/layouts/` 保存页面/模板结构，新增 schemaVersion 和受控样式字段。
- `site.json`、`appearance.json`、`home.json` 等现有文件尽量复用。内容仍有唯一来源，布局节点通过 binding 引用；不会再维护两套同名文字。
- 现有配置先经适配器转为 PageDocument，再形成可回退的显式迁移；迁移前备份，不能静默重排线上页面。
- Astro 侧新增递归布局渲染器与内置组件注册表；现有 Header、Footer、PostCard、Sidebar、TableOfContents 等成为可配置组件。
- 编辑器与生产构建使用同一套 Astro 渲染器。选择框、拖动手柄和操作消息仅在本地开发预览中注入。
- 文章 URL 与章节锚点生成逻辑保持；自定义页面新增时检查保留路由、文章地址和归档地址冲突。

### 4.6 保存与外部编辑

拖动过程只改变内存草稿并更新预览，不每移动一个像素就写磁盘、重启服务。操作结束生成历史项，自动保存到本地恢复区；点击保存或发布时将已验证数据原子写入博客文件。

文件监听排除 node_modules、dist、.git 和缓存。VS Code 或其他窗口修改磁盘文件时，通过文件指纹检测冲突，提供对比/重载/合并，不能覆盖外部修改。

系统不能可靠读取或代替 VS Code 保存尚未落盘的编辑缓冲区。发布读取磁盘版本，在发布摘要中显示文件版本；用户在 VS Code 中仍需要正常保存正文。无需输入任何命令。

## 5. 文章、素材与页面管理

### 5.1 文章

文章列表支持搜索、标签/分类/年份/草稿筛选、排序、封面缩略图和本地变更状态。操作包括新建、复制、打开 VS Code、编辑元数据、内置 Markdown 编辑/预览、草稿切换、归档与恢复。

复用现有 createPost 函数创建 index.md 与 img；文章标题变动不自动改变 permalink。改日期或目录时提示网址影响，只有明确修改网址才改变路径；提供旧网址跳转映射。

元数据更新使用 frontmatter 解析与定点替换，不重排或格式化整篇正文。正文在两个编辑入口之间通过文件监听同步。删除先进入本地回收区；发布时清楚列出线上将移除的文章。

内置正文编辑器支持 Markdown、高亮、基础工具栏、图片粘贴/拖入和预览。首版不要求把整篇 Markdown 变成自由画布或开发完整富文本编辑器。

现有 `draft: true` 表示不生成线上页面，源码仍可能随 Git 同步；界面要如实区分页面发布状态与源码上传状态。

### 5.2 素材

- 本地导入、拖放和剪贴板粘贴图片，显示缩略图、尺寸、格式、文件大小与引用位置。
- 文章图片继续放在各篇 img；全站图片、背景、音频和组件素材放入各自公共素材目录。
- 重命名/移动时更新受管理的引用，先显示影响范围；无法解析的自定义源码引用不自动猜测。
- 优先做无损原图保留和网站输出优化；按需生成 WebP 等派生文件，不覆盖唯一原图。
- 已引用资源删除需先处理引用；清理未引用素材使用可恢复操作，不凭简单文本匹配永久删除。
- 磁盘绝对路径不写入网站配置，保存为项目相对路径或资源 ID。

### 5.3 页面、导航与友链

图形界面管理菜单顺序、名称、路径、显示状态，以及友链/导航条目、分类和图标。创建页面时可选择是否加入菜单。

模板修改、页面结构修改与条目内容修改有明确入口；通过画布选中元素可以跳到相应内容列表，减少来回寻找文件。

## 6. 指令集成与任务执行

不要求用户输入 bash/PowerShell 指令。管理端显示操作名称、进度、结果和可展开日志，底层复用已有脚本和 Git。

| 按钮 | 主要底层操作 |
| --- | --- |
| 新建文章 | 复用 scripts/new-post.mjs 的 createPost |
| 在 VS Code 编辑 | VS Code CLI，使用独立路径参数和 --goto/--reuse-window |
| 开发预览 | npm run dev，检测端口与健康状态 |
| 生产预览 | npm run build，再启动 npm run preview |
| 检查博客 | check:content、check、check:links、test（按任务范围执行） |
| 检查发布隔离 | check:release，扩展至新管理端私有文件 |
| 安装/修复依赖 | npm ci，日志显示下载与错误阶段 |
| 同步远端 | git fetch、状态比较、必要时安全快进 |
| 发布 | 本地校验、Git 提交/推送、Actions 部署与状态追踪 |
| 备份/恢复 | 按范围生成本地快照或恢复选择的文件 |

覆盖当前 package.json 的全部任务入口：dev、build、preview、check、new、check:content、check:links、check:release、test 均进入上述图形操作；edit 由新桌面入口替代。backup、migrate 和 verify-migration 放入“高级维护 → Hexo 迁移”区，只有旧工程存在时可用。迁移默认先预演、展示差异，再执行已有的防覆盖检查；不能把迁移当作日常更新操作反复应用。管理端新产生的启动、打包、组件校验等任务也在开发/维护面板提供图形入口。

操作服务使用固定命令与参数数组，不把标题、文件名、组件配置拼接进 shell。若 Windows 工具入口必须使用 .cmd，则采用专门的受测适配器，不开放任意命令执行接口。

每个任务记录状态：等待、运行、成功、失败、取消；保存阶段、耗时、错误和重试入口。同一项目的保存迁移、依赖安装和发布互斥；只读扫描可以并行。构建等耗时工作放入独立子进程，不阻塞桌面界面。

取消只终止管理端启动的进程树；已经上传的提交或已经触发的远端部署不能伪装为撤销。应用关闭时显示后台任务情况并妥善停止自身服务。

首次设置向导检测 Node、Git、VS Code、GitHub CLI、项目目录、仓库与分支。缺少依赖时提供按钮引导和明确错误，不让用户猜命令。复用现有 SSH/Git 登录；触发和追踪 Actions 另需 GitHub API 身份，优先复用 GitHub CLI 登录。首次 GitHub 身份授权需要用户在官方登录流程中完成，之后日常发布不再手写命令。

## 7. 一键发布的完整定义

首次配置时确认仓库、源码分支、工作流、站点地址，默认读取当前 source/origin；今后发布面板持续显示目标与改动摘要。点击明确标注目标的发布按钮即授权这一次提交和上线，正常流程不重复弹确认框。

流程：

1. 验证并保存管理端的页面设计和内容修改。
2. 检查 Git 状态、当前分支、登录与网络，fetch 远端并识别落后/分叉状态。
3. 在安全情况下快进同步；有冲突则进入图形化差异与冲突处理，不自动覆盖、不强推。处理后重新检查。
4. 执行相关内容/类型检查、生产构建、链接和私有文件隔离检查；错误直接关联到页面或文章。
5. 显示/使用发布面板已有的提交说明，暂存应发布文件并提交；若无改动则支持重新部署已有提交。
6. 推送到配置的源码分支。
7. 通过 GitHub CLI/API 触发当前工作流的 deploy=true，记录本次运行 ID。
8. 追踪构建、上传与 Pages 部署，核对运行 head_sha 与本次提交。
9. 部署完成后检查线上版本信息和关键页面，再显示发布成功与网址。

现有工作流保留“普通推送只检查”的语义。为管理端调用补充 request_id、expected_sha 等输入/运行标识：若分支在推送与手动触发之间变化，拒绝部署不匹配的版本，不能错误宣称发布了已检查版本。需区分 push 检查运行和本次手动部署运行；不能简单抓取“最新一条运行”。

支持暂停后的继续追踪与分阶段重试：Git 推送完成、Actions 失败时显示“源码已上传，网站未更新”，重试部署不重复制造提交。离线时可以编辑、保存、预览；发布连接失败不影响本地成果。

历史功能区分本地编辑快照、Git 提交、线上部署三种记录。恢复线上版本采用选择历史提交重新构建部署或生成回退提交，不使用强推改写历史。

## 8. 可导入组件规范

### 8.1 组件与管理端扩展的边界

本次组件接口指博客访客功能和可拖入页面的区块。首版不开放拥有本机文件/Git 权限的任意管理端插件。

内置布局与内容组件使用受控 Astro 渲染器；外部组件首版使用预构建的 HTML/CSS/JS 与资源包，优先在 iframe 沙箱中运行。不会仅凭扩展名就承诺兼容任意 Astro、React、Vue 或 npm 包；这些源码需要先按规范封装并构建。

### 8.2 包结构与清单

导入本地文件夹或 .blog-component.zip，规范至少包括：

```text
component.json
entry.html
```

组件配置由 JSON Schema 自动生成简洁属性面板，支持文字、数值、开关、颜色、选项和素材选择器。资源选择器存资源 ID/相对路径，不能透传本地文件系统访问能力。

沙箱桥采用版本化、验证后的消息协议：初始化、更新配置、宿主主题/视口、组件状态、受限尺寸请求、命名空间存储、销毁等。每个实例使用独立 ID、来源校验和会话标识。首版沙箱组件不是直接在管理端进程调用 mount/unmount，而是通过宿主创建/移除 iframe，并发送生命周期消息。

### 8.3 安装与运行

导入时验证清单、版本、入口、配置、资源路径、大小、能力与文件完整性；拒绝路径穿越、符号链接和压缩包越界解压。不运行包内安装脚本、Node 入口或 npm 生命周期脚本。

安装后可以预览、启停、配置、选择出现页面、定位和响应式显示。更新保留旧版本和配置；不兼容时回退或停用单个实例，不能破坏整个博客构建。删除时列出使用位置并允许移除或保留占位。

只有访客运行必需的已安装文件、清单和实例配置进入博客源码；导入暂存、校验记录和管理端代码留在本地。

默认不授予任意网络请求。组件所需网络域名和能力在导入预览中说明，用户决定是否启用；内容在隔离环境运行，不能调用 Git、发布或读取项目凭据。

### 8.4 首批验证组件

- 音乐播放器：本地音频/已允许的 HTTPS 音源，播放/暂停、切换、音量和实例配置；首次播放由访客点击触发，不能保证浏览器允许自动有声播放。
- 桌宠：导入自己的素材，配置位置、大小和行为，手机端可单独隐藏；动画按需运行，尊重减少动态效果设置。
- 抽卡：可配置卡池、概率、展示和浏览器本地记录。静态站无法保证跨设备一致的抽卡记录、可信全站限量或防篡改结果；这类能力将来需要独立服务接口。

完整首版要求接口和导入闭环真实可用，并通过示例包验证；三个完整特色功能可以按优先级继续开发，不能把预留空容器标记为组件系统完成。

## 9. 技术架构与文件边界

采用 Electron + TypeScript + React 管理界面，Vite 构建前端；Electron 主进程负责窗口与受控本机操作，通过 preload 暴露窄接口。Node 子进程负责 Astro 与 Git 等耗时任务。

Electron 适合复用本项目 Node 脚本并提供文件选择、拖放、VS Code 启动和本地进程管理。代价是包体与内存占用较大；首版优先实现当前 Windows 的可靠工作流程，不在同阶段加入第二套桌面技术栈。

```text
Electron 管理界面
  ├─ 页面画布 / 文章 / 素材 / 组件 / 发布
  └─ preload 窄接口
       └─ 本地项目服务
            ├─ 配置与布局读写、校验、撤销、快照
            ├─ Markdown 与素材管理
            ├─ 任务队列与 Git / GitHub 发布适配
            ├─ VS Code 启动适配
            └─ 本机 Astro 预览进程
                  └─ 与生产相同的布局渲染器

GitHub 仓库 → Actions → dist → GitHub Pages
```

主进程不开放通用 shell、任意路径读取或未经校验的 IPC。管理界面与博客预览隔离，均关闭 Node 集成，启用 context isolation 与 sandbox；校验 IPC 发送窗口，外部网页/组件无法调用管理接口。管理端页面采用本地应用协议，不为写操作开放公网 HTTP API。

Astro 开发预览只监听回环地址，编辑桥只在管理端拥有的本地开发会话启用；生产构建不注入编辑脚本、选择标记、会话令牌或管理路由。保留 Web 安全策略，不通过关闭 webSecurity 解决跨域。

建议目录：

```text
astro-site/
├─ scripts/studio/                 # 本地独立应用包；Git 忽略
│  ├─ desktop/                     # Electron / preload
│  ├─ ui/                          # React 界面与画布
│  ├─ core/                        # 文件、历史、任务、发布
│  ├─ schemas/
│  ├─ tests/
│  └─ package.json                 # 管理端依赖与博客依赖分开
├─ scripts/artifacts/studio/       # 本地可运行包、验收产物
├─ .cache/studio/                  # 私有状态、恢复历史、日志、会话
├─ src/config/layouts/             # 要发布的页面布局数据
├─ src/components/layout/          # 博客用布局渲染器
├─ src/components/widgets/         # 博客用访客组件宿主
├─ public/uploads/                 # 全站公共素材
├─ public/widgets/                 # 已安装组件的访客运行文件
└─ docs/                          # 规范与操作说明
```

这是目标结构，不表示这些目录已实现。

管理应用的 userData、sessionData、日志和打包输出也定向到博客私有目录；不默认把状态写入其他项目或更改系统设置。GitHub 授权信息不进布局 JSON、不进 Git、不进日志；新增登录配置写入项目私有区域，并使用系统提供的加密能力保护敏感内容。

首版输出可双击的 Windows 便携程序，放在博客内的忽略目录，附带启动入口。安装版和跨平台适配不是首版验收前提。首次依赖准备通过向导完成；离线编辑不代表首次安装依赖无需网络。

## 10. 兼容、迁移与发布隔离

- 使用本地快照和新开发分支开展实现，当前线上版本继续工作；不对旧 Hexo 原始目录进行迁移式覆盖。
- 保留目前已经验证的新文章路径、相对图片、permalink、旧图片映射和章节锚点。
- 先让当前页面通过新的渲染器重现现有效果，再允许可视化修改；默认导入不能改变网站外观。
- schema 版本升级采用显式迁移、备份、验证和可回退记录；升级失败继续读取旧数据或提供恢复入口。
- 扩展 Git 忽略与 release 检查，既检查 dist，也检查已跟踪的管理端私有文件。管理端目录不能用 git add -f 加入博客仓库。
- 博客在缺少整个 scripts/studio 和私有缓存的干净源码检出中仍能通过 CI 构建。
- 本地管理端自身备份与博客 Git 同步分开，避免用户误以为推送博客已经备份管理程序和编辑历史。

## 11. 分阶段实施与验收

阶段可以逐步演示，但最终交付必须覆盖三条主线，不能把某阶段中间界面视为全部完成。

| 阶段 | 主要交付 | 阶段验收 |
| --- | --- | --- |
| A. 基线与应用骨架 | 布局/组件/任务 schema，现有配置适配草案，本地桌面壳，项目与依赖检测 | 双击启动；识别真实项目；显示文章和服务状态；不改线上 |
| B. 页面设计闭环 | 同源渲染模型、自动排版/自由画布、图层、文字图片背景、撤销/保存、三个断点 | 真实首页完成增删拖拽缩放与保存，重启保留，构建效果一致 |
| C. 内容与指令中心 | 文章/页面/素材/导航友链管理，VS Code 衔接，内置基础 Markdown 编辑，任务队列 | 新文章到图片、预览全流程不用命令；外部编辑不会被覆盖 |
| D. 发布与历史 | Git 状态和差异、提交推送、Actions 调用、版本核对、重试与恢复 | 正常发布一键完成；失败区分上传/部署状态；冲突不会强推 |
| E. 组件系统 | 包清单与 SDK、导入/验证/配置/卸载、沙箱、示例组件 | 一个外部示例包无需修改博客页面源码即可导入、布置和发布 |
| F. 集成与便携交付 | 兼容性、私有文件隔离、Windows 打包、迁移与使用说明 | 完整首版验收通过，再退役原文字工作台 |

A 阶段会先做自由画布与 Astro 实际预览的最小技术验证；若同一渲染器下的坐标/交互有问题，先解决再扩展属性面板。D 阶段的线上验收使用明确标记的试发布内容，执行实际发布前显示具体目标和改动。

## 12. 完整首版验收标准

1. 双击启动，无需用户手写启动、构建或上传命令；依赖缺失有可操作的向导。
2. 在真实首页拖入文字和图片，改变背景、大小、位置、层级、分栏与模块顺序，保存重启后保持。
3. 独立编辑手机布局，不破坏桌面；测试长标题、空列表、超长文章和窄屏。
4. 新建文章自动生成 index.md 与 img，点击打开 VS Code；标题/摘要/标签/草稿状态可图形化修改。
5. 管理端内导入/粘贴图片可用于正文、封面和背景，文章与站点预览均可读取。
6. 新建页面可配置路径与菜单；旧文章与旧锚点检查继续通过。
7. 本地保存与撤销可恢复；同时用 VS Code 修改时不会静默覆盖；应用异常退出可恢复已自动保存的草稿。
8. 点击发布能覆盖保存、检查、构建、提交、上传、部署追踪和线上版本确认；构建失败不能继续上线。
9. 网络失败、Git 分叉、路径含空格/中文和重复点击有明确处理；不生成 shell 注入，不强推。
10. 合规示例组件无需修改站点页面源码即可导入、配置、显示与卸载；组件故障可单独关闭。
11. 关闭桌面应用后线上博客正常；公开产物和源码仓库不包含本地管理端、会话、日志或凭据。
12. 从不含管理端的干净源码检出完成博客构建，发布输出与管理端生产预览采用同一渲染规则。

测试侧重数据迁移、保存冲突、任务失败恢复、发布版本对应、组件边界与实际画布操作；复用现有内容/链接/隔离检查，不为每个普通按钮重复实现测试。

## 13. 当前阶段不额外承诺的能力

- 任意第三方 npm/Astro/React/Vue 包零改造直接导入。
- 所有自由画布自动得到完美手机布局。
- Git 冲突无需用户判断内容即可全自动合并。
- 没有远端服务时实现跨用户、跨设备的可信状态。
- 浏览器无交互自动有声播放。
- 重新开发一个完整 VS Code 或 PPT 功能集合。

这些边界不影响本次三条核心要求的实现，避免用无法兑现的“一键”或“任意”替代明确接口。
