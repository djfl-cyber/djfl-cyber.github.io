# Blog Studio 使用说明

Blog Studio 是当前 Windows 博客的本地桌面管理程序。博客继续使用 Astro、Markdown 和原来的 GitHub Pages 地址。

## 启动与目录

双击博客根目录的 `Blog Studio.cmd`。常用操作均在窗口中完成。兼容入口 `npm run edit` 也会打开桌面程序。

管理程序位于 `scripts/studio/`，本地草稿、历史、备份、身份配置位于 `.cache/studio/`，便携包和验收副本位于 `scripts/artifacts/`。这些目录和启动器均被 Git 忽略。只有网页需要的布局、内容、素材、访客组件和构建脚本会进入博客源码；发布只上传 `dist`。

不要将本地管理包上传到源码仓库，也不要将 `.cache` 复制到公开目录。制作的便携包不包含登录、文章草稿、浏览器配置或历史记录；这些个人状态如需换机保留，可单独备份整个项目的本地目录。

## 新建和编辑文章

1. 进入“文章”，点击“新建文章”，填写标题。文章标识可自动生成，也可以指定。
2. 默认同时建立 `index.md` 和 `img`，可勾选创建后在 VS Code 打开。
3. 内置 Markdown 编辑器支持正常 Enter、Backspace、撤销、高亮、保存和侧边正文预览。`Ctrl+S` 保存到博客文件。
4. 直接粘贴剪贴板图片、拖入图片，或点工具栏的图片按钮。文章新图片进入本篇 `img`，Markdown 使用相对地址，VS Code 也可预览。
5. “整页预览”显示保存到磁盘的真实文章模板；正文侧边预览显示内置编辑器的当前内容。
6. 在属性面板修改摘要、日期、分类、标签、封面、目录和草稿状态。修改标题不会改变网址。需要改网址时使用独立按钮，旧网址会保留跳转和原章节锚点。

内置未保存内容会进入本机恢复草稿，下次打开可继续。VS Code 的未保存缓冲区无法被管理端读取，发布前需在 VS Code 正常保存。两边同时修改同一文件时，会要求对比与选择，不会静默覆盖。

`draft: true` 不生成线上文章页面；草稿源码仍属于 Git 源码仓库。文章回收站保留整篇文章及其图片，可恢复到原位置；原位置有文件时不会覆盖。

在 VS Code 中写作时，从管理程序的文章编辑器点击“VS Code”，会同时打开博客工作区和该文章。先复制图片或截图，再在 Markdown 正文中按 `Ctrl+V`，图片保存为本篇 `img/image.png`（重名自动编号），插入 `![alt text](img/image.png)`；按 `Ctrl+S` 保存。已安装的 Paste Image 扩展也配置到同一 `img` 目录。已有窗口可重新从管理程序打开文章以加载项目配置；单独打开文件而没有博客工作区时，VS Code 不会加载博客的 `.vscode/settings.json`。

## 页面设计

点击“预览”或进入“页面设计”启动独立的本机 Astro 服务。首次启动可能稍慢，后续直接切换页面。

- 左侧选择首页、独立页面、共用页头页脚或文章等模板。模板会影响所有使用它的页面。
- 修改页头或页脚文字：选择“共用页头 / 共用页脚”，再点击对应图层，在右侧直接修改标识、作者、寄语、小字或导航文字，点击“保存到博客”。画布中双击页头 / 页脚也可打开文字编辑框，应用后再保存。它们与“设置”共用同一份内容；作者名称会同时影响页头和页脚，版权年份仍自动计算。
- 画布点击选中，Shift 多选，空白容器内拖动框选。双击文字编辑；拖动选框移动，拖动手柄缩放。
- 图层支持复制、删除、分组、锁定、隐藏、前后顺序、移动到容器、对齐和等距。右侧调整文字、边框、背景、图片焦点及布局。
- 自动排列适合正文、文章列表和长内容；自由画布适合装饰、横幅和浮层。自由画布要给父容器合适高度，可使用按内容调高。
- “修改全部设备”设置基础值；关闭后为平板或手机单独设置覆盖，可恢复继承。画布缩放比例不等于网页实际宽度。
- 保存前用“三种尺寸检查”查看越界，手机布局需自行核对。任意自由摆放不会自动变成良好的手机排版。
- 顶部指针按钮切换编辑/交互模式。交互模式用于真实链接与组件操作。
- 左上角加号新建页面，可复制当前布局并加入菜单。常用设计可保存为本地模板。

“页面信息与回收站”管理自定义页面的名称和网址，自动同步对应菜单并保留旧址跳转。回收会同时移除菜单入口，恢复会带回页面和菜单，遇到网址被占用时会停止。先保存当前画布，再修改页面信息。内置页面的网址固定。

新建、改址、回收、恢复及安装组件后，管理端会刷新自己启动的预览服务，因此可能短暂等待几秒。高级用户直接修改路由文件后，可点画布工具栏“重载真实预览”。这不会停止其他终端启动的预览。

拖动和输入先写本地草稿；点保存才写博客布局与关联文字。`Ctrl+Z` 撤销，`Ctrl+Shift+Z` 重做，`Ctrl+S` 保存。

## 文字、导航、友链与素材

“设置”中的站点、外观、首页、菜单、页面、友链、导航、配文分组提供完整字段表单，可添加条目、调整顺序和显示状态。用“查找本组文字或设置”按字段名称或现有文字搜索；“撤销本组修改”重新载入磁盘版本；Ctrl / ⌘ + S 保存当前分组。头像与背景可从素材库选择。外观保持浅色质感，装饰与背景可以继续自行设计。

点击“效果预览”在同屏查看已保存的博客。可切换首页、各栏目、404 和文章页面，保存设置后自动刷新；也可点击“浏览器打开”查看完整宽度。预览不提供本机写入接口。

原浏览器文字工作台已退役，网页和页脚不再提供管理入口。原有两份文字备份已导入“设置 → 项目与工具 → 维护与备份”，标记为“原文字备份（已导入）”，仍可对比并选择恢复。

素材库支持导入、缩略图、尺寸、引用位置、复制网站地址、生成 WebP 派生图和回收恢复。原图不会被优化覆盖。重命名或移动会更新可识别的 Markdown、封面与 JSON 引用；自定义源码引用无法可靠改写时保留原地址副本。旧迁移图片受保护，以免破坏原网址，需要变化时请先导入新副本。

使用“文章配图 / 页面素材 / 全部素材”切换用途，再按图片、音频、视频筛选。按文章目录、旧站文章图片目录和实际文章 / 页面配置引用识别用途；同一图片供文章和页面共用时，两组中均可找到。详情显示用途与所属文章，可搜索文章标题。新导入的全站素材归“页面素材”；文章编辑器中导入或粘贴的图片归当前文章。文章图片选择器默认显示配图，页面图片选择器默认显示页面素材。选择其他文章或页面的图片用于当前文章时，会复制到当前文章的 `img`；当前文章已有图片会直接复用。

点击“扫描未引用”查看候选，勾选后移入回收站。扫描会排除旧站原图、源码引用和本机文章/布局/设置/组件草稿中的引用；执行回收前还会逐项核查版本与引用，期间新增引用的素材会跳过。无法解析的配置或文章应先修复，再清理素材。没有永久批量删除按钮。

## 检查、预览与备份

“设置 → 本地项目 → 维护与备份”提供构建、完整检查、内容/类型/链接/隔离检查、测试、依赖修复、远端获取、安全快进同步及生产预览。日志位于下方任务记录，可展开查看或取消本机任务。

同步遇到未提交内容、分叉或冲突时会停止，不会强推或覆盖。请在 VS Code 的源代码管理界面核对、合并并保存，再回到管理端刷新。当前版本不替代完整 Git 合并编辑器。

“备份博客内容与配置”保存文章、布局、配置、公共素材和项目配置。点“对比与恢复”只恢复勾选文件，并再次校验磁盘版本。文件保存历史还能分别恢复保存前/后的版本。多文件修改中断时会显示待复核事务，核对对应文件后再标记已处理。

“备份本机草稿与历史”另存本机设计、文章、设置与组件草稿、模板、回收区和保存历史，不包含登录凭据、浏览器配置或日志。两类备份均可在列表中对比与选择恢复。便携包保存程序本身；换机时请分别保留博客、程序包与需要的私有数据。

应用正常关闭前会保留当前编辑草稿并停止自身预览。运行中的任务会提示如何处理；已推送的提交和已经开始的远端部署不会随关闭而撤销。

## 发布

1. 在内置编辑器或 VS Code 保存希望上线的内容。
2. 进入“发布”，核对仓库、源码分支 `source`、工作流 `build.yml`、站点地址和改动摘要。
3. 首次缺少 GitHub CLI 时，点击“安装项目专用 GitHub CLI”。程序下载官方便携包并核对 SHA256，仅写博客目录。
4. 点击“在浏览器登录”，在 GitHub 官方页面完成授权；验证码在任务日志中。应用不会替你完成身份授权。现有 SSH 推送继续使用本机 Git 身份。
5. 填提交说明，点击明确标注目标的发布按钮。若保留了未保存本地草稿，可先回去保存，或明确选择本次只发布磁盘版本。
6. 程序从候选源码副本检查、构建；检查期间源码变化会终止。通过后提交、推送并触发这一次部署。
7. 点“追踪与验证”，或保持自动追踪。只有本次运行、提交、请求标识与线上 `version.json` 都匹配，才显示发布成功。

普通 Git 推送只检查。首次部署需要把新增工作流输入推送到 GitHub，仓库也应已启用 Actions 和 Pages。若 GitHub 要求环境审批，需在本次 Actions 页面完成。程序不会把“源码已上传”当成“网页已更新”。失败或中断后可从记录继续追踪、重试上传/部署；历史源码恢复到工作区后按正常流程重新提交发布，不改写远端历史。

## 组件

在“组件”导入文件夹或 `.blog-component.zip`，核对清单展示的能力与外部来源后安装。默认停用，新建实例后可配置文字、颜色、数字、开关、播放列表和素材。

浮层按指定页面和位置显示，可在手机隐藏；页面区块实例可在设计器的“功能组件”菜单插入。启停和配置保存后看真实预览。版本更新保留旧包，可选择新版本并验证配置；不兼容时切回旧版本或停用。

配置改动会自动保存为本机草稿，切换界面或关闭窗口也会保留。重开实例配置可继续草稿；外部修改与当前草稿冲突时，逐项选择后保存。不同版本的配置不兼容时，可使用“此版本的默认配置”重新填写；原版本仍保留。

首版支持预构建 HTML/CSS/JS 沙箱组件。Astro、React、Vue 或 npm 源码需要先封装构建。导入不执行安装脚本或 Node 程序。未使用版本可卸载；使用中的版本需先移除实例，页面会保留空占位。

音乐播放器示例已提供。示例声音为生成的短提示音，实际使用请在配置中选择自己的音频；播放由访客点击触发。桌宠、抽卡可使用同一接口继续制作，当前未附带这两个完整功能。

组件作者可参考 [组件规范与 SDK](blog-components.md)。

## 便携与开发维护

维护面板可检查/构建管理端、制作便携 ZIP。便携目录包含 Electron、Node 和编译后的界面，不依赖全局安装管理程序；Git、VS Code 和博客依赖仍需在目标电脑可用。把包中的启动器和 `scripts` 合并到同一版本博客根目录即可。

日常便携使用不需要管理端开发依赖。需要修改程序、运行其测试或重新打包时，先点击“准备管理端开发依赖”；博客依赖缺失则点击“修复博客依赖”。首次启动便携 Node 时，Windows 可能询问网络访问；本机预览只监听回环地址，可取消公共/专用网络授权。

本地代码和验收记录保留在 `scripts/studio/` 与 `scripts/artifacts/`；`docs/blog-studio-progress.md` 记录实施证据。不要用复制整个工程到 `public` 的方式部署。
