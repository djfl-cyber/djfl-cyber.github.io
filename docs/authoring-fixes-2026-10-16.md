# 写作与设计四项问题修复

日期：2026-10-16。仅修改博客内的本地管理程序与项目级 VS Code 配置，未提交、推送或部署。

## 剪贴板图片

本机 Electron 44.7.2 已不提供 `clipboard.readImage()`，改用异步 ClipboardItem API；旧调用会报 `clipboard.readImage is not a function`。实现已兼容当前 `read()` / `getType()` 和旧便携运行时，并处理无图片、读取失败、大小限制。文字复制也等待异步写入完成。接口依据 [Electron 剪贴板文档](https://www.electronjs.org/docs/latest/api/clipboard)。

原生界面测试又发现，文件导入结束后 React 尚未提交只读状态解除，CodeMirror 的插入方法就被调用，导致文件存在但正文没有图片链接。现在先同步解除本次导入的编辑锁，再插入 Markdown。已在真实桌面按钮中验证保存、相对路径与侧边图片显示。

## VS Code 图片目录

原打开入口只传单个文件，未保证博客是当前工作区；旧目标规则依赖工作区根目录。现在同时打开博客目录和文章，并使用匹配文章路径的规则及明确的 `${documentDirName}/img/${fileName}`。启用内置 Markdown 图片粘贴；对本机已安装的 Paste Image 扩展设置项目级路径覆盖，不改用户全局设置。内置操作依据 [VS Code Markdown 文档](https://code.visualstudio.com/docs/languages/markdown)。

在博客验收副本实际通过管理程序打开 VS Code，确认窗口属于博客工作区；正文末尾按 Ctrl+V 后生成 `![alt text](img/image.png)`，按 Ctrl+S 保存，磁盘文件确实位于文章 `img` 下。

## 页头和页脚文字

这两个图层原来是整体组件，只有普通文字和链接图层提供文字编辑。现在右侧增加组件文字字段，双击画布组件也可编辑。页头包含标识、作者、小字和各导航文字；页脚包含作者、寄语和小字。关联文字通过现有布局事务保存到站点、通用配文和菜单配置，继承草稿、撤销重做、文件历史与外部修改冲突检查。不会改写菜单网址和无关设置。版权年份继续自动生成。

已通过原生界面修改并保存页头标识；服务测试验证页头、导航和页脚的持久化、历史及冲突拒绝。

## 素材用途

素材库增加“全部素材 / 文章配图 / 页面素材”及数量，卡片与详情显示用途，详情与搜索包含所属文章。依据文章归属和实际引用分类；旧文章目录的未引用原图继续归配图；共用图片可在两组找到。识别引用时跳过代码块示例，不搬动或重写现有图片。

文章图片选择器默认配图，页面选择器和设计器素材栏默认页面素材。文章选择其他来源的图片时，将原始文件复制到本篇 `img`；选择自己已有的图片直接复用。页面使用文章图片时生成全站副本，两份文件保留各自用途。WebP 派生图继承原图用途，后续实际引用仍可更新分类。
